# 半导体数据分析实践

## 1. 数据泄漏：最常见也最致命的错误

数据泄漏（data leakage）指训练数据中包含了预测时不可能获得的信息，
导致离线指标虚高、线上完全失效。

在半导体数据里，泄漏的来源比通用机器学习场景更多：

- **随机切分时序数据**：这是最典型的错误。同一批（lot）的多个 die、
  同一次工艺的多个测量点天然高度相关。如果随机划分训练集与测试集，
  同一批的数据会同时出现在两边，模型实际上是在「背答案」。
- **使用了未来才产生的特征**：例如用「最终量测结果」去预测「该批是否异常」，
  但量测是在异常发生之后才做的。
- **使用了下游工序的信息**：用后道工序的数据预测前道工序的结果。
- **跨批次统计量**：用全量数据计算的均值/标准差做归一化，
  把测试集的信息泄露进了训练集。

**正确做法**：
- 按**时间切分**（time-based split）：训练用历史，测试用之后的数据
- 或按**批次/机台分组切分**（GroupKFold）：同一 lot 或同一 chamber 只出现在一侧
- 归一化统计量只在训练集上计算，再应用到测试集

## 2. 类别不平衡

良率与失效数据通常极度不平衡：失效 die 可能只占千分之几。
此时准确率（accuracy）是完全无意义的指标——全预测为「正常」就能得到 99.9%。

应当使用：
- **召回率（Recall）**：漏报率是关键，漏掉一个真失效代价高
- **精确率（Precision）** 与 **PR 曲线下的面积（PR-AUC）**：不平衡场景下比 ROC-AUC 更敏感
- 若业务上两类错误代价不同，应使用**代价敏感**的阈值选择，而不是默认 0.5

## 3. 特征工程：按 step 分段

半导体设备的传感器数据（trace）有一个重要特点：
一次工艺（recipe）被划分为多个 **step**（例如抽气、起辉、主刻蚀、过刻蚀、吹扫），
每个 step 的物理机制完全不同。

因此**必须按 step 分段提取特征**——每段的均值、斜率、方差、峰值、积分量等，
而不能把整条 trace 拍平了直接丢给模型。把不同物理机制的阶段混在一起，
模型学到的统计规律没有物理意义，也无法解释。

## 4. 缺失值

半导体数据的缺失往往**不是随机的**：
量测是抽检，测哪些点本身有工艺原因。因此不能用均值简单填充。

可选做法：
- 把「是否缺失」本身作为一个特征（缺失模式可能携带信息）
- 用同一批其他位置的测量值做插补
- 对于关键参数缺失的样本，直接标记为不可用于训练

## 5. 模型漂移监控

设备维护、更换零部件、新 recipe 上线、原料批次变化，
都会使数据分布随时间变化，模型会逐渐失效。

监控手段：
- **预测残差监控**：跟踪预测值与实际值之差，用 CUSUM/EWMA 检测残差分布的漂移
- **输入分布监控**：用 PSI（Population Stability Index）或 KL 散度监控特征分布
- **触发重训的规则要事先定义**：不能等模型明显变差才动手

## 6. 指标选择与基线

报告模型效果时，必须给出**基线对比**。常见基线：

- 用历史均值预测（naive baseline）
- 用上一批的值预测这一批（last-value baseline）
- 纯规则/纯人工经验的判定结果

只报 RMSE 或准确率而不给基线，是评审时最常见的减分点——
因为没有基线就无法判断这个数字是好是坏。

## 7. 可解释性

在需要工程师信任的场景，模型可解释性与精度同样重要：

- 树模型可直接输出特征重要性
- 线性模型系数有方向性含义
- 复杂模型可用 SHAP 等归因方法，但要注意归因结果的稳定性

工程师不接受「模型说异常但说不出为什么」——这会导致系统被弃用。

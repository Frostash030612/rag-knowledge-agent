# 芯片测试程序基础

## 1. 测试程序的结构

一个测试程序（Test Program）由一系列**测试项（Test Item）**按顺序组成。
每个测试项规定：测试条件（电压、时序、温度）、测量内容、
以及**判定限值（Test Limit）**。

测试项按类别划分：

- **DC 测试**：开路/短路（Open/Short）、漏电流（IIL/IIH）、
  输出驱动能力（VOL/VOH）、电源电流（IDD）
- **AC 测试**：频率、建立/保持时间、传播延迟
- **功能测试（Functional Test）**：写入特定数据模式再读出比对，
  验证存储阵列的功能正确性

## 2. 测试限值与 SPEC 限值的关系

这是测试领域最容易被误解的一点：

- **SPEC 限值**来自产品规格书，是产品对外承诺的性能边界
- **测试限值**是测试程序实际使用的判定门限

两者通常**不相等**。测试限值一般比 SPEC 更严格（guard band，保护带），
原因有三：测试设备的测量误差、接触电阻带来的额外偏差、
以及温度与电压条件在测试时无法完全复现客户使用条件。

设置 guard band 是在「测试成本（良品被误判为不良，即 overkill）」
与「客户风险（不良品流出，即 escape）」之间的权衡。

## 3. Test Coverage 与 DPPM

- **测试覆盖率（Test Coverage）**：测试项能捕获的缺陷类型占全部可能缺陷的比例
- **DPPM（Defective Parts Per Million）**：每百万件中的不良品数，
  是衡量流出风险的核心指标

覆盖率不足会导致 escape（漏检），覆盖率过高会拉长测试时间、推高测试成本。
测试时间直接决定测试成本，因此**减少冗余测试项**与**提高覆盖率**是持续的矛盾。

## 4. 冗余分析与测试压缩

DRAM 阵列中包含**冗余单元（redundancy）**，用于替换失效单元。
冗余分析（Redundancy Analysis）决定用哪些冗余单元去替换哪些失效单元，
目标是最大化可修复的 die 数量。

修复（Repair）通常在晶圆测试阶段进行，用激光或电熔丝烧断的方式完成。
修复后需要重新测试以验证修复效果。

## 5. 测试数据与良率分析的关系

测试产生的数据是良率分析的核心输入：

- **Bin 数据**：每个 die 的测试结果分类，用于画 wafer map
- **Fail Bin 分布**：哪一类测试项失败最多，直接指向工艺或设计问题
- **测试项参数值**：不仅记录 pass/fail，还记录测量值，
  可用于分析参数的边缘分布（near-miss 分析）

**Near-miss 分析**是一个很有价值的实践：
关注那些「刚好通过」的 die，它们的参数已接近限值，
如果工艺继续漂移就会失效。这是提前预警的重要信号。

## 6. 测试环境的数据特点

测试数据在建模时有几个特点需要注意：

- **数据量极大**：一次晶圆测试可能产生数百万条测量记录
- **高度结构化**：格式固定，容易解析，但需要处理缺失测试项
- **强时序性**：测试有严格的先后顺序，且测试机状态会随时间漂移
- **多站点（multi-site）并行测试**：同一台机器并行测试多个 die，
  站点之间的细微差异会成为系统性因素，建模时必须纳入考虑

# 工艺控制体系：APC / R2R / FDC / VM

## 1. APC 的整体分层

先进工艺控制（Advanced Process Control, APC）不是单一算法，而是一套体系。
它通常分为三层，三层构成一个闭环：

1. **FDC（Fault Detection and Classification）**：从设备传感器数据实时判断
   「这台机台这一批是否正常」。属于**检测**层。
2. **VM（Virtual Metrology）**：预测无法每片实测的量测值，提供反馈信号。
   属于**观测**层——因为控制需要观测值，而实测值不够。
3. **R2R（Run-to-Run）**：用上一批的结果反馈调整下一批的工艺参数。
   属于**控制**层。

闭环逻辑：FDC 发现异常并拦截 → VM 提供连续的观测值 → R2R 据此调整下一批的输入参数。

## 2. R2R 控制与 EWMA 控制器

R2R 的核心思想是「用上一批的偏差修正下一批的设定」。

最常用的控制器是 EWMA（指数加权移动平均）控制器，其更新公式为：

```
u_k = u_(k-1) + K · (T − y_k)
```

其中：
- `u_k`：第 k 次 run 的控制输入（例如刻蚀时间、曝光剂量）
- `T`：目标值（target）
- `y_k`：第 k 次 run 的实测结果
- `K`：控制增益，0 < K ≤ 1

直观解释：若这次量出来偏低（y_k < T），下一次就把输入往上调一点。

### K 的权衡

| K 取值 | 响应速度 | 对量测噪声的敏感度 | 输入波动 |
| --- | --- | --- | --- |
| 大（接近 1） | 快，但容易过冲 | 高 | 大 |
| 小（接近 0） | 慢 | 低 | 小、平稳 |

K 的选择本质是在「跟踪真实漂移」与「抑制量测噪声」之间做权衡。

工程上还有两项必要处理：
- **约束裁剪（clip）**：工艺参数有物理极限，例如刻蚀时间不能超过 90 秒，
  控制器输出必须裁剪到可行域内。
- **异常剔除**：如果这批货被 FDC 标记为异常，或量测设备本身异常，
  则不应把该测量值用于更新控制器——否则噪声会被写进控制器的记忆里。

对于带漂移的过程，还会使用 dEWMA（double EWMA）来同时估计均值与斜率。

## 3. FDC 的多变量方法

设备传感器产生的是一条条时序曲线（trace），变量之间高度相关。
因此 FDC 常用多变量统计方法：

- 先用 **PCA（主成分分析）** 降维，提取主元空间
- 计算两个统计量：
  - **T² 统计量**：衡量样本在主元空间内的偏离程度，反映**过程变化幅度**是否异常
  - **SPE（Squared Prediction Error），也称 Q 统计量**：衡量残差空间中
    变量间相关结构是否被破坏

两个统计量必须一起看：T² 正常但 SPE 超限，往往意味着变量之间的**关系**变了
（例如两个本应同步变化的参数出现背离），这类故障单看单变量控制图是发现不了的。

## 4. 误报与漏报的权衡

FDC 系统最大的落地障碍不是算法精度，而是**误报（false alarm）过多**。
当工程师每天收到上百条误报后，会习惯性忽略告警，系统就失效了。

因此在 FDC 的指标设计上，不能只看检出率，还要看：
- 报警的**准确率**（报警中有多少是真问题）
- **平均提前量**（能否在缺陷产生前报出）

同时应建立**工程师处置结果回流**机制：工程师确认是真问题还是误报，
这些标注是后续调阈值和训练分类器最宝贵的样本。

## 5. 何时不该用 LLM 做控制

需要明确一条边界：**实时闭环控制不能用大语言模型**。原因有三：

1. **延迟不可控**：LLM 推理延迟在秒级甚至十秒级，而控制环要求在毫秒到秒级。
2. **输出不可复现**：控制动作必须可复现、可审计，概率模型的输出不满足这个要求。
3. **安全责任不可转移**：把工艺控制的安全责任交给概率模型，在合规上不可接受。

LLM 在 APC 体系中合适的角色是：**事后的分析、检索证据、解释结论、编排分析流程**，
而不是产生控制量。
